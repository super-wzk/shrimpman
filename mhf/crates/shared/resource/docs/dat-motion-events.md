# DAT[390]／DAT[391] 动作事件

这两张表由 HD `mhfo-hd.dll` 的原生动画更新路径消费，独立于 DAT[389] 的招式步骤、
派生条件与事件，也独立于特效资源中的动作事件。以下地址以该 DLL 的 `0x10000000`
映像基址表示。解析器保留查找键、物理序号、参数和未知字节，不执行操作或随机选择。

## 两级目录

`10AF5140` 初始化 `DAT[390]/[391]` 时，分别在 `10AF78AB/10AF7913`
用 16 位寄存器计算 `DAT[665]` 的低 u16 加 18；加法按 u16 回绕。
结果为零时跳过目录，不解引用根指针。

基础分组编号为 0–17。`1099B860/1091EB70` 读取 `DAT[665]` 的完整 u32，
逐行匹配 DAT[664] 中的四个 u16 键；匹配行 i 对应分组 `18+i`，未匹配时返回分组 18。
目录长度与匹配表计数的读取宽度不同，因此 `Directory.additional_groups` 保留完整 u32，
`Directory.count` 按初始化路径的低 u16 计算，不把高位数据静默改写。

每个分组头八字节：

| 偏移 | 类型 | 字段 |
| --- | --- | --- |
| +0 | u16 | count：查找条目数 |
| +2 | u16 | unknown_02 |
| +4 | u32 | records_pointer |

`1099B130/1091EB00` 按 word 读取分组数量。每个查找条目也为八字节：

| 偏移 | 类型 | 字段 |
| --- | --- | --- |
| +0 | u16 | key：原生二分查找键 |
| +2 | u16 | count：事件数 |
| +4 | u32 | events_pointer |

`1099B180` 在 `1099B18E/1099B19D` 读取 word 数量与键并二分查找。
键与目录中的物理条目序号是两个字段；解析器不排序或重编号，也不将键转换成文件路径。
指针在原生初始化时重定位；离线输入使用 `base=0`，已重定位输入使用实际 DAT 基址。
解析器只验证所需的根头范围，不依赖初始化已改写的签名字节。

根目录、分组与事件表分层校验；坏组或坏条目不阻止读取其他组。
非空表拒绝空指针、DAT 头内指针和越界范围，空表不解引用残留指针。

## DAT[390]：16 字节操作事件

`1099AF70` 从动画帧区间选择事件，`1099B04C` 每次前进 16 字节。
`1099AFE8..1099B013` 的汇编向操作回调传入全部七个参数：

| 偏移 | 类型 | 字段 |
| --- | --- | --- |
| +0 | u16 | frame |
| +2 | u16 | operation |
| +4 | u16 | arg_a |
| +6 | u16 | arg_b |
| +8 | u8 | arg_c |
| +9 | u8 | arg_d |
| +10 | u16 | arg_e |
| +12 | u16 | arg_f |
| +14 | u16 | arg_g |

操作表位于 `11A42488`。回调自身决定参数的有符号解释和用途；例如 `103362E0`
会将三个 word 解释成有符号三维偏移。这个局部分支不能推广到全部操作，
因此 `CommandEvent` 保留七个原始调用参数，未知操作编号也保留。
反编译器按某个回调原型显示的参数数量不代表实际推入的参数数量，特别不能丢弃 `+9`。

## DAT[391]：22 字节分派事件

`1091E7B0` 在 `1091EA9A/1091EAAC` 按 22 字节前进。

| 偏移 | 类型 | 字段 |
| --- | --- | --- |
| +0 | u16 | frame |
| +2 | u16 | dispatch_kind |
| +4 | u8 | condition |
| +5 | u8 | unknown_05 |
| +6/+8 | u16/u16 | choice_0.id / weight |
| +10/+12 | u16/u16 | choice_1.id / weight |
| +14/+16 | u16/u16 | choice_2.id / weight |
| +18/+20 | u16/u16 | choice_3.id / weight |

`1091E7E9` 的条件选择涉及运行时武器或状态分支；未确认的编号不补造枚举。
`1091E8AE..1091E928` 按四个原始权重选择 ID，权重总和为零时使用 choice_0。
`1091E932` 检查 ID `0xffff` 并跳过分派；`1091E94F` 根据 dispatch_kind 调用不同原生函数。
空候选的 ID、权重及未知字节仍全部保留，不压缩槽位。

## 查看、编辑与验证

工作台分别按需展开“动作操作事件（390）”与“动作分派事件（391）”。
来源路径采用物理序号，例如 `mhfdat.bin#390/0/0/events/0/arg_d`、
`mhfdat.bin#391/0/0/events/0/choice_3/weight`。
字段绑定在当前解码数据层内，嵌套容器起点也计入字节范围。

普通测试覆盖计数字段宽度、回绕、未知字节、重定位、空表、损坏隔离和单字段编辑；
`tests/dat_motion_events.rs` 从 `MHF_RESOURCE_GAME_ROOT` 的原始 ECD／JKR 文件验证
全部分组、查找条目和事件的记录范围及字节往返，不向仓库加入游戏素材。
这些检查验证文件结构与编辑行为，实际播放、回调及随机选择仍需实机验证。
