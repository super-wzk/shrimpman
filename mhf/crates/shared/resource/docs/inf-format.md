# INF 任务资料目录

`inf` 读取解码后的 `mhfinf.bin`。它是通过文件相对指针组织的任务资料，
不是 offset/size 容器，也不代表任务执行脚本。原始图像始终保留；
解析器不把文件偏移转换为宿主指针，不接受客户端已经重定位的内存图像。

## 文件头与分类目录

`10AFAE80` / `10AFB00B` 的加载与重定位路径确认了下列结构：

| 文件偏移 | 存储类型 | 已确认含义 |
| --- | --- | --- |
| `0x00` | `[u8; 4]` | `inf\x1a` |
| `0x04` | `u32` | 格式版本 `6` |
| `0x08` | `u32` | 保留原值，含义未确认 |
| `0x0c` | `u32` | 根结构长度 `136` 字节 |
| `0x10` | `u32` 偏移 | 计数块，首个 `u16` 是物理分类数量 |
| `0x14` | `u32` 偏移 | 分类表，每项 `8` 字节 |

分类记录包含 `quest_id_limit: u16`、`slot_count: u16`、`slots_offset: u32`。
槽表按 `slot_count` 存储任务记录偏移，每槽 `u32`；零值表示空槽。
重复指向同一任务的槽保留各自物理位置，不去重或重排。

`1041F370` / `10423E90` 按文件顺序扫描分类，在 `quest_id_limit == 0` 或
`requested_quest_id <= quest_id_limit` 时停止，然后仍以
`requested_quest_id % 100` 选择当前分类的槽。零上限不是直接返回无匹配，
它的槽表仍可提供后备记录。首字段是 ID 上限，不是分类枚举、目录下标，
也不能直接推导出完整连续的 ID 区间。物理解析保留终止分类后的数据；
查找行为单独遵循上述原生规则，并检查所选槽是否在文件声明范围内。
若遍历完声明分类仍未遇到停止条件，或者选中分类的槽越界，返回明确错误；
不继续读取声明目录之外的字节，也不把这些情况当成合法空槽。
`1047A820` 对 `ID >= 40000` 改用另一张动态任务表；`Inf::lookup` 只查询
静态 INF，对这部分 ID 返回无匹配，不从分类尾部猜测动态任务记录。

## 任务前缀与文本

已确认的任务字段如下，偏移相对该任务记录起点：

| 偏移 | 存储类型 | 已确认含义 |
| --- | --- | --- |
| `0x28` | `u32` 偏移 | 文本指针表，包含 `8` 个 `u32` 字符串偏移 |
| `0x2e` | `u16` | 任务 ID |

任务记录目前只建立能覆盖这些字段的 `48` 字节最小前缀。
不能用相邻任务指针之差作为完整记录长度，也不把前缀后的字节当成可删除填充。
所有未解释数据仍属于完整 INF 源图像。

字符串偏移同样相对完整 INF 起点。文本表和字符串分别验证边界；
零字符串指针保留为空槽，非零字符串须在图像内找到 NUL。
工作台用 CP932 显示文本，保留原始字节，不从槽序号猜测业务标题。

## 工作台接入

分类先列出，任务槽和文本按需展开。字段使用现有 `Reader` / `Binding`，
保存其真实 buffer 和字节范围；分类上限、槽指针、任务 ID、文本指针及字符串
均通过现有编辑和重解析流程处理。指针目标损坏时保留对应错误和可修复的指针字段。

字符串只在已确认容量内编辑，保留终止符；不自动搬移任务记录或未解析数据。
修改解码内容后，由现有包装层重建 ECD / EXF / JKR，输出仍为完整源文件。
原始字节导出只导出所选节点实际声明的范围，不将最小任务前缀冒充完整任务文件。

分类和文本字段布局来自共用的 `resources/layout.json`；构建时生成
`inf_layout.rs`，避免工作台维护另一份分类步长和文本偏移常量。
测试覆盖截断、越界、零槽、别名、原生 ID 查找、文本容量及嵌套包装编辑。
格式与编辑验证不等于已验证客户端接受任意修改后的任务资料。
