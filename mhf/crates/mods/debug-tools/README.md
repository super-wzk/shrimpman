# Debug Tools

本 crate 提供调试快照、命令接口、独立调试窗口及游戏内 HUD。对外提供方是 `mhf.debug`，
接口 ID 保持 `mhf.debug-tools.v1`。命令调用成功表示进入游戏线程队列，
执行结果通过后续快照和游戏消息观察。`headers` feature 公开 `api::define_header`。

`provider` 在 i686 Windows 启用调试状态、Hook 和 eframe 窗口。`DebugToolsMod::new(registry)`
由 [`mhf-debug`](../debug/README.md) 包装，共用其 Context 与 Hook 所有权；attach 绑定 Base 的 Quest 控制接口，
不创建另一份任务会话。任务能力由 Base 提供，游戏内名称按 CP932 读取。

运行时在游戏线程执行命令并发布不可变快照；桌面 UI 线程持有筛选、草稿、录制查看与回放状态。
窗口使用自己的事件循环和渲染设备，快照刷新不依赖游戏 Present。
桌面线程采用线程级 DPI awareness，禁止 winit 改写整个进程的 DPI 设置。
Debug 的普通启动接口覆盖 Login fallback，因此本地调试启动不会先运行登录窗口；
同一调试会话只创建一个桌面事件循环，隐藏和再次显示都复用它。

stop 同步移除游戏 HUD／输入回调，归零操控输入，然后关闭桌面窗口并等待 UI 线程退出；
detach 卸载 Hook，prepare_release 归还额外游戏引用。
原生状态保留到游戏 DLL 卸载后销毁。现有真实客户端测试位于本 crate，
需提供 `MHF_TEST_CLIENT` 指向游戏 DLL，`MHF_TEST_QUEST` 指向调用方提供的任务 BIN/JKR，再运行忽略测试。

## 调试操作

启用和启动方法见 [Debug](../debug/README.md)。使用同一个 `mhf-launcher`，
通过 `[mods."mhf.debug"] enabled = true` 自动覆盖默认 Login；任务文件由 Quest 设置提供。

调试面板默认在独立系统窗口中打开，可自由移动和调整大小。
在游戏或调试窗口按 **F7** 显示或隐藏；点击系统关闭按钮也会隐藏窗口，保留草稿和选择状态。
调试窗口统一采用 Hunter 紧凑密度，按钮、输入框和选择框使用一致的控件高度。
宽窗口使用可调宽度的左侧导航，窄窗口使用换行页签。
工具栏保持在页面顶部，列表和编辑区域分别滚动并使用剩余空间；
下拉列表按当前窗口的上下剩余空间限制高度。
“任务”页集中显示任务编号、运行状态、换区、交战详情、重开任务和结束调试；
其他页直接使用可用编辑空间，“帮助”按当前页显示。

- **外观**：选择性别、脸型和发型后，在当前任务内立即热替换。切换性别时同步替换
  全身装备模型；脸型和发型使用对应性别的客户端目录，显示编号与模型编号。头盔可能遮挡发型。
- **装备**：按武器种类或防具部位筛选、搜索名称或编号，点击“换装”后在当前任务内热替换，
  刷新模型、技能与招式资源；保留所在区域、位置、任务进度和怪物操控状态。
  装备名称、编号与模型编号来自已加载的 DAT；防具显示当前角色性别对应的模型编号。
  操作只修改当前进程中的临时角色。
  当前已装备项可点击“重新加载”，重新读取同编号的武器和全身外观资源；修改替换文件后无需先换成其他装备。
  武器换装或重新加载会恢复招式跟随装备，使动作资源和装备特效按当前武器类别绑定；防具换装保留招式来源。
- **幻化**：位于“装备”后，按头、胸、腕、腰、腿筛选防具，搜索名称或编号后应用外观。
  使用客户端原生防具幻化字段，保留实际装备、属性、技能和招式来源；应用时回到待机并刷新模型。
  每个部位可单独“恢复原样”；换装、切换性别、换区和重开任务会重新应用当前幻化选择。
  头部幻化需要先装备头部防具，实际防具与幻化防具需支持当前角色性别；之后卸下头盔或切换到
  不兼容的性别时，选择仍会保留，但对应幻化暂不显示。幻化只保留在本次调试进程中。
- **招式**：选择任意招式来源武器，点击“触发”调用原生招式状态机。
  跨武器时保留当前装备记录，在重载任务期间切换本地猎人的招式分类，让后续原生加载器
  载入对应的动作资源；加载完成后触发选中的招式。“招式跟随装备”恢复正常对应关系。
  招式列表使用客户端动作目录中的编号，未确认名称的招式不推测名称。
  “定义”在独立可缩放窗口中显示所选武器招式的动作步骤、动画编号、事件及调用参数，
  位于调试系统窗口内，不占用招式列表高度；点击其他招式的“定义”更新同一浮动窗口。
  动画、攻击资源与来源路径使用公共资源引用组件，例如 `motion/w04.mot#4/5`；
  已解析路径可复制，原生编号、武器与风格保留在悬浮提示中。未解析的动画保留原始编号，
  攻击资源从实际 `dat/mhfsdt.bin` 解码后的原目录解析，例如 `mhfsdt.bin#2/attacks/8`，
  使用原文件目录索引，不把类别键或运行时排序索引当作目录槽。首次需要攻击资源时在原生任务侧读取，
  并在本次调试进程中缓存目录；读取遵循客户端已有的资源替换。缺失、损坏或记录越界时保留
  `mhfsdt.bin` 文件身份、类别、子类别及记录号，错误放在悬浮详情中，UI 线程不读取资源文件。
  事件的触发条件与操作说明独立显示，攻击目标通过同一组件呈现。
  定义、步骤和事件共用资源层的类型与来源范围，例如 `mhfdat.bin#389/4/0/events/1`；
  按步骤分组显示不会改变原始事件序号，未知字段与操作参数保留。
  当前读取 `DAT[389]` 的武器定义；通用动作和怪物原生状态分支尚未覆盖。
- **状态 HUD**：左下角半透明浮层显示装备类型、招式来源、变身状态、动作与动画编号、当前帧和位置。
  不占用页签空间、不拦截鼠标；F7 隐藏调试窗口后仍显示，加载或结算期间隐藏。
  页签正文不设置通用提示区域，操作结果不会挤动列表；定义读取错误只在定义窗口内显示。
  重开任务、结束调试和换区位于“任务”页，不占用其他页的列表或编辑器高度。
  装备、幻化、招式和怪物变身的筛选项使用统一控件样式，以选项文字和搜索占位提示说明用途，不重复显示标签。
- **换区**：“任务”页的区域下拉框显示当前区域，选择其他区域后立即换区，无需额外确认。
  默认古迹地图可在营地 460 与战斗区 461 间切换；优先使用任务入口的落点，没有返回
  入口的区域使用客户端原生出生点。变身时会携带所选怪物，并在载入后恢复操控。
- **怪物变身**：先从完整中文种类列表选择目标，再选择该种类支持的普通、HC、霸种、极怪、至天、辿异种或特殊形态。
  目标列表只显示名称，变种项显示变种编号与对应模型编号；仍可按怪物名称或种类编号筛选。
  例如“HC · 变种1 · 模型094_b”与“极怪 · 变种11 · 模型146_b”；
  每种怪物分别配置变种的名称、编号和模型，界面、状态提示与变身校验共用其目录。
  同一编号不代表同一类别：水龙的变种12是“彼岸岛联动”，怒喰恐暴龙的变种12是“SaGa联动”；
  变种6的已确认活动模型及变种8、15的特殊强化也只对相应怪物开放。
  点击“变身并操控”后重载当前地图、加载所选
  怪物的模型与动作资源，保留原任务怪物，再单独生成并接管一个受控实例。无需场上已有
  该种类；即使与任务目标同种，也不会接管或替换目标。受控实例不注册为主任务目标。
  其他怪物保留 AI，并通过同步到怪物位置的玩家代理锁定你。猎人只在绘制时隐藏；
  攻击玩家代理的命中交给受控怪物的身体与伤害状态处理，受控怪物的攻击可命中其他
  怪物，并排除自己及玩家代理。敌对命中还会放行身体部位对怪物攻击类型的过滤，
  使用独立受击数据副本，保留原来的形状、部位和免疫状态。伤害和受击反应沿用原生逻辑。
  “任务”页的“交战详情”显示双方原生 HP、命中检查次数、确认命中次数和最近一次
  实际扣血；命中计数与扣血分别记录，以区分受击判定和后续生命值结算。
  选择种类后立即显示其真实招式目录，支持筛选、直接触发和绑定快捷键 1–4；
  尚未变身为所选变种时，触发招式会先加载对应怪物与变种，再执行所选招式。
  切换种类会重置为普通变种；切换种类或变种都会清除原来的快捷招式绑定。
  变种沿用当前任务的等级及强化条件，“普通”不会关闭任务强制 HC 等设定。
  同种原任务怪物会共用所选变种的资源与行为。普通任务仅前两个怪物资源槽支持设置变种；
  原任务已启用多怪物扩展时可使用前五个槽，超出可用变种槽会提示更换任务。
  点击游戏窗口后，W/S 相对镜头前后移动、A/D 相对镜头左右移动、Q/E 调试升降、
  Shift 加速；窗口可以保持打开。调试窗口或其他 Overlay 控件有键盘焦点时暂停操控。
  UI 只修改操控设置，游戏 Overlay 从游戏窗口采样按键；在脚本编辑器输入不会发送操控命令。
  输入采样独立于调试面板更新，隐藏窗口后仍可操控；游戏窗口失焦立即归零，停止更新超过 200 ms 也会归零。
  变身镜头默认拉远至至少 1200、俯视 20°，可在“操控设置”里调整距离和
  垂直角度（−60° 至 80°，正值俯视、0° 平视、负值仰视）；恢复猎人后使用原生镜头。
  进入任务原生出口的水平范围可换区；在怪物碰撞处理前探测入口，站在跳崖入口上方
  也会直接触发，不要求继续移动、面朝入口或处于特定高度。入口下方不会反向触发；
  多个入口上下重叠时选择最近的下方入口。目标区域、落点与朝向来自任务入口记录。
  加载期间暂停操控，完成后在新区的原生落点继续使用
  所选怪物，并重新应用镜头距离与垂直角度。怪物自动朝移动方向转身，斜向移动不加速；
  移动方向取镜头朝向在地面上的投影，调整俯仰角不会改变移动速度。
  猎人模型隐藏期间仍同步区域、朝向，并更新原生地图坐标，使地图位置箭头跟随怪物。
  “原生选招”位于折叠的操控设置中，R 可执行一次选招，不是显示招式目录的前置步骤。
  宽窗口的操控设置在右侧独立滚动，可拖动边界调整宽度；窄窗口从页面工具栏打开。
  Backspace 或“恢复猎人”重载原始任务，恢复原有装备和猎人操控。
  变身任务副本只存在于内存，原始 BIN 不变。客户端最多同时载入 6 种怪物资源；
  资源槽已满时选择已载入种类，或恢复猎人后换一个任务。特殊巨型怪物、机关及部分形态仍依赖
  对应地图与任务脚本；当前招式目录只收录能从客户端明确提取或运行中观察到的编号。
- **任务控制**：“重开任务”重新加载同一文件；“结束调试”通知原生主循环退出。

## 怪物与 AI 调试

AI 工作区顶部通过模式选择框切换“现场 / 回放”。源码居中，右侧检查面板提供监视、指令详情和
现场断点；底部显示执行轨迹。检查与轨迹均可收起，拖动分隔线调整宽度或高度，
双击分隔线恢复默认比例，各区域独立滚动。窄窗口或较矮窗口通过“源码 / 检查 / 轨迹”
切换主区域；执行按钮随宽度换行，处理中、暂停和草稿未应用状态显示在工作区工具栏。
工具栏采用带悬浮说明和无障碍名称的图标按钮，按执行控制、源码操作和录制分组；
附加／分离共用一个按钮，图标、选中状态与提示随当前实例的附加状态切换；
暂停／继续、单步、至让出、应用更改、反编译、加载工程、恢复、复制与录制操作直接可用。
禁用按钮保留操作说明，窄窗口随宽度换行。现场和回放均通过系统文件选择器保存录制，
默认文件名为 `mhf-ai-recording.json`，只选择 JSON 文件，覆盖已有文件由系统确认。
导入支持输入文件路径或粘贴 JSON。

现场暂停会定位到匹配版本的源码，编辑器持有焦点时不抢走编辑位置。点击历史轨迹停止跟随，
中央显示录制源码；“定位执行”恢复现场跟随并定位当前源码行。未应用草稿不会显示错误的执行行或绑定行断点。
文本选区使用蓝灰色底与高对比文字；当前执行行使用金色高亮和左侧标记，现场与回放一致。
“监视”页显示当前运行字段。源码行号负责添加行断点，字段旁的红色圆点添加字段变化断点，
已有断点时显示圆点加斜杠，点击移除；字段变化时暂停 AI。删除和清空的垃圾桶图标也使用红色。
检查面板中的“添加断点”
只提供指令位置和操作码条件。录制源码只在中央显示，轨迹开关只在工作区标题栏提供。

切换实例会刷新该实例的脚本描述符和映射，并保留它自己的未保存草稿。已附加的调试会话
在刷新成功后切到新实例；旧实例的迟到回复不会写入当前草稿。更换种类重载时，工作区等待
原生成槽位的新种类实例，不自动选择其他怪物。

“附加”从暂停状态开始，只影响选中的怪物实例。断点支持源码行、逻辑脚本偏移、
opcode 和已捕获字段的变化，可以附加字段条件。条件只读取快照，不执行游戏函数。
断点列表优先显示文件名与行号，完整路径、编号、版本和原始位置放在悬停说明中；
没有源码映射时显示脚本与偏移，删除使用垃圾桶图标。
源码行通过编译器的字节码映射绑定。反编译结果会与声明槽位里的原生字节逐条核对，
一致时无需热替换即可调试源码；草稿与已绑定源码不同或没有对应原生字节时不可绑定。
一条语句产生多个执行位置时会绑定全部位置。生成的分支标记和隐式返回不作为源码断点。

现场逐指令执行仍由原生解释器完成。调试器在固定客户端的入口、分派和退出位置插桩，
保存整数寄存器、标志、x87/SSE 状态、游标和本轮分派计数，暂停时离开游戏线程调用。
继续不重置 999 次原生执行预算。暂停期间世界、动画、感知和其他怪物继续运行；
如果原生模式、lane、stage、重启标志或续行被改变，旧续行失效，需重新附加。
“单步”与“至让出”通过原生触发入口唤醒，并保留帧延迟；不等同于推进整个游戏一帧。
分离时完成仍有效的暂停执行轮次后恢复原生调度。实例卸载、任务重开或 AI 热替换会结束
当前调试会话，最后一段轨迹仍可导出；重新附加生成独立的程序版本。

附加期间自动记录，现场环形缓冲保留最近 1024 条指令，并明确显示已移出的前缀数量。
轨迹包含实例身份、程序版本、调度帧、逻辑游标、原始指令字节、捕获字段变化和退出原因。
指令之间发生的外部字段变化单列为输入变化，不归因于下一条指令。未知原生脚本只记录
实际观察到的指令块；指针不作为离线执行地址导出。源码映射可用时支持定位到源语句。

回放模式载入现场轨迹或导入录制文件，支持前进、后退、定位和检查字段。导入会校验实例、
序号、游标、字段变化、检查点及已捕获脚本字节。回放重建被记录的状态，不执行修改后的
脚本、不调用原生游戏函数，也不承诺覆盖全部引擎输入或副作用。任务结束后仍可使用。

录制与回放核心位于独立的 [`mhf-ai-debug`](../../shared/ai-debug/README.md)，
调试界面的反向单步通过检查点重放恢复已录制状态，不撤销现场已经发生的动作。

启用工具栏的“状态 HUD”图标后，右下角跟随所选实例显示 AI 主状态编号、动作、动画帧和位置。
隐藏 F7 面板后仍显示，控件不拦截鼠标；目标卸载或槽位复用时提示重新选择，不显示旧状态。
开关仅保留在当前调试会话中。

“怪物管理”是独立一级页签，显示选中实例已有的 AI 主状态、动作、动画帧和位置，
并提供种类替换。属性信息目前只读。管理页与“怪物 AI”页共用实例选择和草稿状态。
实例列表来自任务实例池中已加载且持有 AI 块的怪物，按实例槽位区分同种怪物，

AI 为 `.mhai` 文本。已支持的命令使用 DSL，其他已确认宽度的指令保留为 `native(...)`。
可搜索名称或编号选择新种类，点击“替换并重载任务”更新选中目标的出生记录。
通过原生任务加载流程载入模型和 AI；任务进度重置，目标条件与其他出生记录保持原样，

编辑器直接使用调试面板的可用空间，随系统窗口调整大小。
切换实例保留各自草稿；应用、重新反编译、恢复和复制操作共用当前实例与草稿状态。

继承。`81` 指向另一张子脚本表，不能当成主状态引用。每个成功导出的脚本都经过
重新编译的字节一致性检查，但这不是完整原生图导出。
无法确认边界的条目不覆盖，并在反编译文本中报告；`24` repeat、`62` 的执行／跳过宽度差异

## 替换文件与热重载

搭配 `mhf.dat-redirect` 时，先完成替换文件的保存，再执行调试操作：

- **重开任务**：重建客户端注册的全部 77 个 ABN 包的成员偏移／长度索引，再由原生任务清理和加载流程重载资源。
  覆盖武器、防具及这些包内的其他资源，成员变大、变小、后续成员位置移动和移除替换文件均按当前文件处理。
- **直接换装／重新加载**：先刷新同一份 ABN 索引，再使猎人的模型 ID 缓存失效，由原生流程释放旧模型并加载当前文件。
  换装保留任务进度；外观和幻化变更也在加载前刷新索引。
- **怪物模型**：普通和 HD 的 `emmodel*/em*.pac` 由原生加载器直接打开，长度也从当前打开的文件取得，
  不依赖上述 ABN 索引。“重开任务”会清理模型资源池，再读取 PAC 中的模型、贴图和动作。
  修改时需对应客户端实际选用的普通／HD 和变种路径；普通换区可能复用怪物资源，不能代替完整重开。

索引刷新只读取包目录，不解码全部资源；目录无效、分配失败或原生读取队列仍忙时，操作报错并保留原索引。
这不是文件监听：已载入资源需由上述操作触发重读，启动时载入的全局 DAT 数据不在热重载范围内。
当前验证包括目录增减、原生缓存字段及调试 UI 测试；怪物和装备的最终画面、连续重载生命周期仍需在真实游戏内验证。

UI 只发送命令并读取快照，所有角色、装备、动作和场景变更均在原生任务调度线程执行。
Quest Hook 拦截 `connect` / `WSAConnect` 并提供本地任务交付；临时猎人字段由 Debug 启动回调填写。
调试 Hook 通过 Quest 控制接口请求任务重开或变体，不持有任务字节。默认 Login 不激活本地任务会话。
跨武器招式混用属于实验调试功能：此实现没有为每种混搭补齐专属武器计量槽、弹药或附属对象，
这些调试行为尚未逐项进行游戏内验证。
