# 怪物 AI DSL 规范

本文定义怪物 AI DSL 的语法、执行语义、原生编码及使用限制。
格式版本为 `mhf_ai 1;`。完整工程示例见 [examples/monster-ai](../examples/monster-ai/)。

## 1. 工程和入口

一个工程由 `main.mhai` 与它导入的模块组成。文件名和拆分方式由作者决定；
`states.mhai`、`contents.mhai`、`events.mhai` 并非保留名称。
只有入口声明物种、地图以及状态/事件绑定；被导入的模块不声明这些内容。

调试反编译始终读取实例实际使用的 AI。工程目录用于限定覆盖范围，与原生扫描机制分离。
导出与恢复后的反编译统一读取当前任务地图 ID，生成
`maps/<map>/<species>/main.mhai` 及对应的 `map ID;`，不按原生共享关系自动归入 `common`。
脚本内容来自实例 descriptor，不重新选择 AI，也不扫描其他地图来决定工程路径。
该目录表示工程使用范围，不表示脚本是这张地图独有。
`common` 用于组织默认工程和共享模块。

```text
monster-ai/
  common/6/
    main.mhai
    combat.mhai
    movement.mhai
    reactions.mhai
  maps/31/6/
    main.mhai
    special.mhai
```

游戏加载根目录是 `dat/monster-ai`。优先读取
`maps/<map>/<species>/main.mhai`，仅入口不存在时回退到
`common/<species>/main.mhai`。专用工程有语法、读取或编译错误时直接报错，
不悄悄回退。两个入口的绑定不会隐式合并。

```text
mhf_ai 1;
species 6;
map 31;
base native;
```

- `species`：怪物种类 ID，0～255，不是实例槽位。
- `map`：任务地图 ID，不是区域编号。默认入口省略 `map`，地图专用入口声明具体编号。
- `base native;`：只覆盖声明的表项，其余沿用所选实例的原生数据。
- 省略 `base` 表示空基座，用于离线图编译；游戏安装只接受 native 基座。
- 实例槽位和生成序号由调试器管理，不写进可复用工程。

入口路径中的物种和地图必须与声明一致；安装时再与实际目标核对。
省略 `map` 对应 `common/<species>/`；声明地图编号对应 `maps/<map>/<species>/`。
默认工程仅在地图专用入口不存在时作为后备，不表示覆盖所有地图。

## 2. 导入和命名空间

```text
import "combat.mhai" as combat;
import "./movement.mhai" as movement;
import "shared/reactions.mhai" as reactions;
import "#common/combat.mhai" as defaults;
```

- 普通路径相对于当前文件，`./` 可省略。
- `#common/` 相对于**当前入口物种**的默认目录，例如 common/6。
- 不提供 `@/`、`~/` 或绝对路径。
- 规范化后的路径只能位于当前工程目录或当前物种的默认目录内；
  `../` 不能导入其他物种或其他地图的工程。
- 文件读取也检查实际路径。越界符号链接被拒绝；内部符号链接别名要求改用
  规范路径，避免同一文件在编辑器中形成两份不同草稿。
- 规范化后相同的模块只合并一次，允许多个导入别名指向它。
- 导入不重导出另一个模块；引用为 `alias.function`，不支持多级重导出。
- 循环导入、缺失模块、重复别名、导入另一个 main 入口均报错。
- 每个工程最多 128 个文件、源码合计最多 4 MiB。

内置命令名和关键字不能用作函数、模块或动作别名；`handler` 与 `then` 是上下文关键字，
只在 `handler fn` 和 `handle ... then` 中生效，仍可用作普通函数名。
`.` 用于模块成员引用；
`self.flashed`、`self.enraged` 和 `self.target.available`
是内置的只读条件属性，不参与模块名字解析。

## 3. 函数

```text
import "movement.mhai" as movement;

fn attack() {
    movement.prepare();
    action[3:6](0);
    wait(10);
    movement.recover();
}
```

函数没有参数和返回值。使用 `name();` 或 `module.name();` 调用。

每个被调用函数生成独立子脚本。自然结束与 `return;` 都使用该槽位的原生返回指令；
`return;` 可用于 `if/else`、`random` 和 `match` 的嵌套分支。
返回到哪里由解释器保存的游标决定，不提供通用调用栈或任意嵌套的返回保证。
`main` 和匿名状态／事件入口使用各自的自动收尾规则。

```text
fn helper() {
    if self.flashed {
        return;
    }
    wait(1);
}
```

此例中，闪光条件为真时跳过 `wait(1)`，执行 helper 槽位的返回指令。
从未闭合的 `native(...)` 条件中调用 helper 不会将它的返回变成调用方的返回。

### 槽位分配与调用

无注解函数由编译器自动分配槽位，多个调用点共享同一份脚本，不内联。
分配按入口调用关系和源码顺序确定：首次从层级 0 到达的函数使用 table 1，
从层级 1 到达的函数使用 table 15～270，从层级 2 到达的函数使用 table 9。
已有槽位的函数不因后续调用上下文改变位置；未被调用的函数同样分配并检查。
单个生成脚本最多 64 KiB。

`@slot` 显式固定槽位：

```text
fn main() { attack(); }

@slot(table = 1, index = 3)
fn attack() {
    approach();
    action[3:6](0);
}

@slot(table = 15, index = 2)
fn approach() { wait(15); }
```

`table` 是 descriptor 表索引，允许 1、9 或 15～270；`index` 为表内 0～255 槽位。

| 槽位表 | 调用编码 | 自然结束／`return;` |
| --- | --- | --- |
| 1 | `81 index` | `FF 01` |
| 15～270 | `82 (table - 15) index` | `FF 02` |
| 9 | `16 index` | `FF 03` |

注解与函数名、文件名、import 别名无关，跨模块重复绑定会报错。
`main` 是固定主入口，不能标注 `@slot`；状态／事件可以引用带槽位注解的函数。
无注解与有注解函数使用相同的调用和返回规则。

编译时自动槽位避开显式声明。安装 `base native` 工程时，根据实际原生表重新选择空槽，
只重定位编译器生成的调用，不修改 `native(...)` 中的索引，不覆盖继承的非空表项。
显式 `@slot` 则覆盖其指定表项。空槽以当前绑定目标的表为准，不自动回收先前绑定的非空项。
表无法完整读取或没有可用槽位时，安装报错。

调用不因递归、跨层转移或嵌套 `16` 而被拒绝，但它们沿用原生控制流：

- stage 是解释器调用层级，不是 DSL 状态或地图。
- `81` 仅在 stage 0 保存续行，然后设置 stage 1；`FF 01` 取该游标并设置 stage 0。
- `82` 仅在 stage 1 保存续行，然后设置 stage 2；`FF 02` 取该游标并设置 stage 1。
- 同层 `81/82` 为尾跳转，不保留新的续行；编译器不生成该路径调用后的语句。
- `16` 无条件写入自己的单个返回游标，`FF 03` 读取它；二者都不改变 stage。
  再次进入 `16` 会覆盖外层续行，编译器不会额外保存或恢复它。

`native(...)` 原样保留；反编译能恢复的 `81/82/16` 输出为带固定槽位的函数调用，
无法读取的目标保留原指令并警告。

### 目标距离分组

```text
match self.target_distance_group() {
    1 => attack();
    2 => { self.update_target_position(); approach(); }
    3 => ranged_attack();
    4 => chase();
    else => search();
}
```

`self.target_distance_group()` 只能作为 `match` 选择项，不接受参数，
不支持独立调用或作为 `if` 条件。
声明 1～4 个从 1 连续编号的分支，最后必须有 else；支持单语句、代码块及嵌套。
整体直接编码为 `83 00 N 83 01 ... 83 (N+1) ... 83 FF`，不改写距离配置。
从怪物当前配置读取前 N 个距离阈值，选择第一个非负且不小于目标距离的阈值。
因此递增且非负的阈值形成连续距离段；负阈值会被跳过，不假定所有配置都递增。
else 处理没有匹配阈值或目标距离不可用（含无目标）的情况。分支结束后退出 match。
玩家目标读取已缓存的距离；已提交目标类型为怪物时实时计算实体间距离。
原生操作保存选中段编号到 +2586；距离可用时还会保存距离到 +1112。
反编译仅恢复数量、顺序和结构完整的原生块，特殊布局保留 native，并校验字节往返。

### 上下文查询分支

```text
match context.query(4) {
    0 => nop();
    1 => { wait(3); }
    else => {}
}
```

查询在进入 `match` 时仅执行一次，返回字节值，可能有副作用。
编号含义由当前怪物实际绑定的原生回调决定，可涉及任务配置、属性或运行状态，
不同回调的相同编号不保证具有相同含义。
`context` 与 `self` 平级，表示当前 AI 执行上下文，不是全局共享对象。
`context.query(id)` 只能作为 `match` 选择项，不支持独立调用或通用表达式。

查询编号和 case 值均为 `0..255`；必须有 1..255 个严格递增且不重复的 case，
并以 `else` 收尾（可写 `else => {}`）。分支不穿透，支持嵌套及单语句分支。
整体编码为 `79 00 count id`，每个 case 为 `79 01 value`，
最终 `else` 为 `79 02`，结束为 `79 03`。
反编译只恢复可无损重编码的完整、有序布局，其他 `79` 结构保留 `native(...)`。

### 物种组分支

```text
match self.species_group {
    1 => { /* 雌火龙原种及其变体 */ }
    11 => { /* 雄火龙原种及其变体 */ }
    100 => { /* 刻龙 */ }
    else => {}
}
```

`self.species_group` 按游戏的原生物种分组表比较当前怪物和 case 物种。
case 写物种 ID，但比较的是双方所属组的归一化键，不是物种 ID 本身；同组的原种、
亚种或稀少种会互相匹配。该分组不表示飞龙种等生态分类。

case 值为 `0..255`，按源码顺序匹配，首个同组 case 胜出，不要求递增。
`else` 可省略；没有任何 case 匹配时执行 `else`，或在没有 `else` 时继续块后的代码。
编译器不重排、合并或改写 case，因此同组的后续 case 可能不可达。

编码为 `2C 00 count`、各 case 的 `2C 01 species`、可选的 `2C 02` 和结束标记
`2C 03`。反编译保留原始 case 物种 ID、顺序及 `else` 是否存在。

### 区域移动路线配置分支

```text
match self.area_route_profile {
    0 => nop();
    1 => { wait(3); }
    else => {}
}
```

`self.area_route_profile` 表示怪物的区域移动路线配置编号，不是当前区域或目标区域。
编号含义由物种和地图决定，不保证跨物种、跨地图一致。该属性只能作为 `match`
选择项，不带括号。

case 值为 `0..255`，必须有 1..255 个严格递增且不重复的 case，并以 `else` 收尾。
分支不穿透，支持嵌套、单语句分支和提前 `return;`。
编码为 `57 00 count`、各 case 的 `57 01 value:u16be`、`57 02` 和 `57 03`。
反编译只恢复可无损重编码的完整、有序布局；无 else、超出字节范围等其他布局保留
`native(...)`，不补写缺失标记。

### 加权随机分支

```text
random {
    1 => attack();
    2 => defend();
    1 => {
        self.update_target_position();
        retreat();
    }
}
```

每项为非负整数相对权重、`=>` 和一条语句或花括号代码块，允许嵌套。
显式零权重分支保留编号及代码，但不会被随机选择；至少一项权重必须大于零。
每块允许 1～31 项（原生分支选择码为 1～31）。编译器以最大余数法归一化到
32 份：先向下取整，剩余份额按余数降序分配，同余数按源码顺序。
例如 1:2:1 得到 8:16:8；1:1:1 得到 11:11:10，并产生实际份额提示。
正权重归一化为零时编译报错。使用当前实例随机值的低五位，不隐式刷新随机值。
选中分支正常结束后继续执行块后的语句，无需 break；控制转移仍按原语义执行。
编译器生成 `80 00 count`、顺序分支标记和 `80 FF`；反编译仅恢复顺序编号、
非负权重合计 32 且结构完整的分支，其他布局保留 native 以确保字节往返一致。

### 条件块

角度区间使用 `self.target_angle_in(min, max)`：

```text
if self.target_angle_in(45, 135) {
    attack();
} else {
    turn();
}
```

参数固定以度为单位，可写整数或十进制小数，范围 0～360，要求 min ≤ max。
采用 XZ 水平面，自身前方为 0，向右为正：90 为右侧、180 为后方、270 为左侧。
判断当前动作绑定的玩家目标（kind=1、arg1=0、index 非 FFFF）；配置不匹配时为假。
它不等同于 `self.target.available`，不额外检查目标是否同区域或存活。
每个条件直接生成一组 `78 00 min max` / `78 01` / `78 02` 标记，支持可选 else 和嵌套。
边界按最近的 1.40625 度刻度取整，中点向上取，超过 358.59375 的边界截断到该值；
有量化或截断时编译诊断显示实际生效的闭区间。相等边界表示量化后的单一角度。
不支持负数或跨零点区间，也不会自动拆分。小数仅用于此方法的角度参数。
反编译输出原生边界对应的精确度数，保留字节往返；下界大于上界的特殊原生结构
保留 native。`0x20` 的多分支保留 native，不转换为这个条件方法。

```text
fn main() {
    if self.flashed {
        wait(15);
    } else {
        nop();
    }
}
```

`if` 和 `else` 必须使用花括号，支持嵌套，`else` 可省略。
`self.active` 对应原生 `08` 条件，检查实体阶段字段 `actor +1040 == 0`。
它表示怪物处于可运行常规 AI 的正常活动阶段；演出、进入／离开及其他特殊过渡阶段为假。
它不等同于生命值检查，也不表示是否处于地面或飞行动作。
`self.flashed` 表示当前怪物闪光致盲计时器（actor +2914）非零，
`self.enraged` 表示怒态标志（actor +2726）非零，检查当前怒态，区别于
刚进入怒态时触发的 `rage_entered` 事件。
`self.target.available` 检查当前选中的玩家目标：下标非 `0xFF`、记录有效、
目标切换状态 `+2042 == 0` 且与怪物处于同一区域；无目标时为假。
它不检查生命值、视线或攻击距离，不等于存活、可见或可攻击。
这些属性均为只读布尔条件，不是方法，
也不能赋值。不支持其他条件属性、`!`、
`&&`、`||`、比较表达式或 `else if`。

带副作用的条件使用方法形式：

```text
if self.check_tracked_players() {
    // 仍保有至少一个玩家的追踪／仇恨记录
} else {
    // 已无记录，当前目标下标也已清除
}
```

该方法检查玩家追踪位集合 `+2687`：非零时为真，不修改当前目标；
为零时先将当前目标下标 `+2612` 设为 `0xFF`，再走假分支。
没有 else 时也执行该清除。它不会选择新目标，不保证玩家当前可见，
也不等于当前目标存在。仅允许在 if 条件中使用，必须带空括号；不支持参数、
属性写法或独立方法语句。副作用由原生 `02 00` 执行，不额外插入清除指令。

`self.mode_is(mode)` 是另一个条件方法，接受内置枚举 `Mode`，
例如 `if self.mode_is(Mode::Attack) { nop(); }`。
类型和枚举成员使用 PascalCase，通过 `::` 引用；`.` 用于属性、方法和模块函数。
`Mode::Normal = 0`，`Mode::Attack = 1`。不接受数字、其他类型或未知成员，
不支持自定义枚举声明；内置类型名 `Mode` 不可作为函数、动作或导入别名。
它先将当前模式 `+2680` 保存到快照字段 `+2600`，再判断是否等于参数；
无论真假都会保存快照，但不会切换模式。模式不是 states 的槽位编号。
`Attack` 对应原生 `EM_MODE_ATTACK`；`Normal` 是普通／非攻击模式的 DSL 命名。
反编译遇到未知原生值时保留原生条件标记为 `native(...)`，确保字节不丢失。
必须带一个参数，只能用于 if 条件，支持可选 else 和混合嵌套。

实体目标选择使用独立方法语句，接受玩家槽位数字或内置枚举 `TargetStrategy`：

```text
self.select_target_entity(TargetStrategy::SameArea);
self.select_target_entity(3); // 06 01 00 03：玩家槽位 3
```

| 策略 | 原生单字节指令 | 行为 |
| --- | --- | --- |
| `AllowedAreas` | `52` | 从已追踪玩家中按原生优先级选择，允许同区域及物种配置许可的其他区域 |
| `SameArea` | `53` | 同区域原生复合选敌，包含零累计值时按当前随机值选择、物种专用保留和覆盖规则 |
| `GroundFiltered` | `5F` | 同区域并按自身脚下碰撞面编号分组过滤，再按原生优先级选择 |
| `PlayerOrMonster` | `7E` | 按原生配置决定先尝试玩家或怪物，失败后尝试另一类，同时绑定动作目标和目标类型 |
| `TrackedBySlot` | `12` | 取已追踪玩家中槽位编号最大者，同时绑定动作目标并修改原生事件标志；不是最后加入或最后发现者 |
| `LeaderTarget` | `58` | 复制原生配对首领的已提交玩家目标，同时绑定动作目标；首领不存在则清空 |

这些枚举一一对应完整原生算法，保留全部副作用，不代表独立的随机、最远或最高仇恨算法。
`52/53/5F` 通常先选累计值至少 50000、其次至少 30000 的候选，档内多人取距离最远者，
否则取累计值最大者；原生目标保留路径可能提前返回。`5F` 普通区域按自身编号
1～3 筛选玩家 1～3，否则筛选玩家 4～10，自身编号 0 时无目标；特殊区域有编号归一化。
该分组不保证目标与自身同高度或路径可达。
`12` 的追踪集合为空时不会主动清空旧目标参数。
首领配对为野猪→大野猪王、黄速龙→黄速龙王、蓝速龙/白速龙→蓝速龙王、红速龙→红速龙王。
`TargetStrategy` 为保留类型名；策略参数必须使用上述具名成员，不接受未知成员。
数字参数编码为 `06 01 00 slot`，表示玩家记录数组的槽位，不是玩家和怪物共用的实体编号。
编码范围为 0～255，实际有效槽位取决于游戏中的玩家记录；字节可编码不代表对应槽位存在。
该形式只设置动作目标参数，不修改策略选出的当前目标，也不隐式调用绑定或坐标更新。
后续 `update_target_position()` 或动作提交按原生逻辑解析目标：在 `Attack` 模式下，
若已有当前选中目标，原生逻辑会以其低 4 位覆盖指定槽位，因此不代表强制锁定该玩家。
反编译仅将 `06 01 00 slot` 恢复为数字调用，其他目标组保留 `native(...)`。
该方法可用于主入口、状态、事件和辅助函数，不能作为 if 条件。
反编译将这些单字节指令输出为上述方法调用；`native(...)` 可显式保留原始字节。

已经选择目标后，可以为后续动作绑定玩家目标：

```text
self.bind_awareness_target(); // 11
self.bind_current_target();   // 13
self.set_mode(Mode::Normal);  // 40 00
self.set_mode(Mode::Attack);  // 40 01
self.update_target_position();       // 4D
self.select_target_point(0);     // 06 02 01 00
self.select_target_point(Direction::Forward500); // 06 06 00 00
self.increment_random_value(); // 84
```

`set_mode()` 调用原生模式切换逻辑，不切换状态槽；原生条件可能阻止切换，
回到 Normal 时会清理玩家追踪及相关感知数据。`update_target_position()` 按当前目标配置
解析动作目标实体或坐标，不执行目标选择策略或移动动作。
`increment_random_value()` 将实例保存的 16 位随机值加一（溢出回绕），
不重新生成随机数、不立即选择目标。`0x7B` 和 `0x84` 均反编译为此方法，
编译统一生成 `0x84`。导出的往返校验仅允许指令位置上的 `7B → 84` 归一化，
不修改操作数中的 `0x7B`。`0x40` 的非标准非零操作数保留为 `native(...)`。

`select_target_point(index)` 从当前物种、当前区域的路线点表选择目标，索引编码范围为
0～255；实际有效索引取决于该区域的点数，编译器无法静态验证原生表长度。
该方法只配置目标，不隐式刷新坐标或执行移动；需要时随后调用 `update_target_position()`。
它不修改当前玩家目标选择策略。

同一方法也接受内置枚举 `Direction`，无需包装参数：

```text
self.select_target_point(Direction::Forward500);
self.update_target_position();
```

枚举直接表示原生固定的“方向＋距离”组合，不接受第二个距离参数：

| 方向 | 500 原生坐标单位 | 1000 原生坐标单位 |
| --- | --- | --- |
| 前 | `Direction::Forward500` → `06 06 00 00` | `Direction::Forward1000` → `06 06 08 00` |
| 左 | `Direction::Left500` → `06 06 01 00` | `Direction::Left1000` → `06 06 09 00` |
| 右 | `Direction::Right500` → `06 06 02 00` | `Direction::Right1000` → `06 06 0A 00` |
| 后 | `Direction::Backward500` → `06 06 03 00` | `Direction::Backward1000` → `06 06 0B 00` |

解析坐标时，以怪物自身位置和当前朝向计算对应距离的偏移目标点。
与数字参数相同，方向参数只配置目标，不隐式更新坐标或执行移动。
`Direction` 是保留类型名；参数必须使用表中的八个成员之一，不接受额外参数。
反编译将 `06 02 01 index` 和上述八种方向编码恢复为 `select_target_point`；
非零尾参数及其他 `06` 形式保留 `native(...)`，保证字节不丢失。

`bind_awareness_target()` 从察觉事件来源掩码 `+2821` 中取槽位编号最大者，
写入动作目标参数，但不改写当前目标 `+2612`。
`bind_current_target()` 将当前目标 `+2612` 写入动作目标参数；无目标 `0xFF`
转换为动作上下文的 `0xFFFF`。两者均设置原生玩家目标命令类型与参数组，
只影响接下来提交的动作，不执行新的目标搜索，也不接受参数。

语义层以条件和两条语句分支表示 `if`；原生编码层为条件提供开始、
可选的 else、结束标记。`self.flashed` 对应 `39 00`、`39 01`、`39 02`。
`self.enraged` 对应 `35 00`、`35 01`、`35 02`，可与闪光条件混合嵌套。
`self.target.available` 对应 `54 00`、`54 01`、`54 02`，同样支持混合嵌套。
`self.check_tracked_players()` 对应 `02 00`、`02 01`、`02 02`。
`self.mode_is(value)` 对应 `0B 00 value`、`0B 01`、`0B 02`。
没有 else 编码的条件不能使用 else；不隐式模拟未确认的原生行为。

分支中可调用函数或使用当前入口允许的 `reset`、`restart`、`transition`。
花括号只结束条件块，不结束脚本。分支内的提前转移不视为整个函数终止，
编译器保守保留块后的自动收尾（即使两条分支均已转移），以保持原生字节往返。
分支内的原生条件必须在同一分支内闭合，不能跨越 DSL 花括号。
主入口和匿名状态／事件入口分支中的 `return;` 通过重排后续代码实现：
仅将剩余语句放入未返回的分支，不重复求值已有条件。
重排可能复制后续代码，生成脚本仍受 64 KiB 上限约束。
子脚本函数的 `return;` 直接生成其槽位对应的 `FF 01/02/03`，无论槽位是显式还是自动分配。
未闭合的原始 `native(...)` 条件内不能使用入口的 `return;`，因为没有可重排的 DSL 分支结构；
子脚本的返回保留原生条件闭合标记。
反编译将完整的单 else `02`/`0B`/`35`/`39`/`54` 条件结构还原为该语法；无法表达的结构保留 native。

### 请求处理器

游戏会根据任务配置、玩家行为和自身状态选中一个行为请求。DSL 用声明与调用两部分表达处理它的协议：

```text
fn main() {
    handle dispatch_request() then {
        reset;
    }

    // 没有请求，或处理器放行时，从处理器之后继续
    wait(1);
}

handler fn dispatch_request() {
    process_request(); // 尾调用，沿用下层结果
}

handler fn process_request() {
    if self.flashed {
        pass;
    }

    clear_requests();
}
```

- `handle 处理器() then { ... }` 在进入时检查一次请求状态；没有请求则整段跳过。
  处理器正常结束后执行 `then`，并继续执行 `then` 之后的语句。
- `then` 是调用方自己的代码，`reset`、`restart`、`transition` 保持原语义；
  它不能使用 `return;` 或 `pass;`。
- `handler fn` 是专用调用约定：只能通过 `handle` 或另一个处理器的尾调用进入，
  不能被普通函数调用，也不能作为状态或事件入口。
- `pass;` 只在处理器内有效，表示放行并结束当前处理器，使调用方跳过 `then`。
- `return;` 与自然结束表示保留接管，不表示请求已完成或被清除。
- 处理器之间只能尾调用：下层可能已经放行，上层不应再执行其他动作。
- 不支持嵌套 `handle`：原生协议只有一个共享字节，不是可重入的上下文栈。

清除请求与处理结果是两件事：`clear_requests(); return;` 清除请求后仍执行 `then`，
`clear_requests(); pass;` 清除请求并跳过 `then`。

编码固定为 `1B 00 01`、`0C 04 01`、处理器调用、`2B 00 04 01`、`then` 内容、
`2B 02`、`1B 02`；处理器同样占用独立槽位，`pass;` 生成 `0D 04` 加该槽位的返回指令。
调用层级沿用原生规则；若调用是尾跳转或覆盖了返回游标，不能保证执行到接管检查点。
反编译只在完整协议、目标子脚本和返回结构可无损重编译时恢复这套结构；
带 else、缺少后续检查或目标另有普通调用点的 `1B` 结构保留 `native(...)`。

## 4. 状态和事件绑定

```text
states {
    patrol => patrol_loop;    // 1
    fight = 4 => fight_loop;   // 4
    recover => recover_loop;  // 5
}

events {
    player_detected => reactions.on_player_detected;
    rage_entered => reactions.on_rage_entered;
}
```

状态格式为 `别名 [= 索引] => 函数引用;` 或 `别名 [= 索引] => { 代码块 }`。
事件同样支持 `事件名 => 函数引用;` 和 `事件名 => { 代码块 }`。
函数引用不加括号，入口生成一次对子脚本的调用及该入口的收尾；
代码块则作为匿名入口直接写入表项，不额外分配子脚本槽位。
两种形式可混用，入口的作用域、控制转移和自动收尾规则一致。
入口绑定使用 `=>`。

```text
states {
    fight = 1 => { self.bind_current_target(); attack(); }
    patrol => patrol_loop;
}
events {
    player_detected => { self.bind_current_target(); }
    awareness => on_awareness;
}
```
省略索引时第一项为 1，之后按上一项索引加 1；显式索引改变后续起点。
函数式工程的状态索引范围 1～255，同一个块内不允许重复索引或别名。
状态 0 固定由入口文件中的 `fn main()` 定义，不在 states 中重复绑定。
`main` 是启动／重置入口，不是一次性初始化函数；不能作为辅助函数调用，
也不能在导入模块中声明。`base native` 下省略 main 表示继承原生状态 0。
不继承原生的函数式工程必须定义 main。其他状态的原始索引保持不变。
事件只接受下一节列出的七个英文名称。
事件声明顺序不影响绑定；不支持数字槽位、显式索引、自动分配或自定义事件别名。
重复事件名报错。不同状态或事件可以引用同一函数。
不存在的函数、把原生命令当入口函数、给函数传参均报错。

```text
fn main() {
    wait(15);
    transition fight;
}

fn fight_loop() {
    combat.attack();
    restart;
}

fn patrol_loop() { restart; }
fn recover_loop() { restart; }
```

`transition` 是状态切换指令，目标是入口定义的状态别名；
返回 main 使用 `restart;`（原生 `04`），不允许 `transition main;`。
原生 `07 00` 反编译为 `native(0x07, 0x00);`，不改写成不同字节的 restart。
它不返回当前位置，不是收尾关键字。通过普通函数调用执行到 transition，
同样转移整个主状态执行流程，调用方不再继续。

主状态入口函数自然结束（或执行 `return;` 返回入口）时，编译器自动补 `FF 00`，
重置到主状态 0。辅助函数返回后继续调用处，不在辅助函数末尾补重置。
反编译省略 main 和普通状态末尾的 `FF 00`，由编译器补回；条件分支中的
提前重置显示为 `reset;`。导出时校验重新编译后的字节一致。
`reset;` 对应 `FF 00`，重置主状态及活动事件通道，可在主状态和事件中显式使用；
`reset forget_target;` 对应 `FF F7`，在重置执行流程时额外清除当前目标槽的
追踪标记、追踪计时、感知累积和目标优先值；它不直接把当前目标编号写成 `0xFF`。
`forget_target` 只作为 `reset` 的修饰项，不是独立关键字或可调用方法。
它不等同于事件自然收尾。`restart;` 对应 `04`，仅在主状态中重新进入 main。
两者均为语句关键字，不接受 `reset()`／`restart()` 调用写法；reset 可带上述 forget_target 修饰项。
已有显式 transition、restart 或终止指令的末尾不重复补齐；编辑器源码不被改写。
事件调用路径中不能使用 transition/restart。自动收尾只作用于自然到达末尾的路径。

低层内联条目可单独解析，事件必须使用固定名称：
`states { idle { ... } }`、`events { awareness { ... } }`；
这一形式不自动补尾，不能与函数式绑定混用。反编译导出使用函数式绑定。
低层内联模式允许显式指定索引 0；函数式工程只能通过 main 定义入口。
状态裸条目 `name = N;`、事件裸条目 `awareness;` 表示显式清空。
`base native` 下未声明的条目继承原生；状态 0 不允许清空。

## 5. 事件自动收尾

```text
fn handle_first() {
    movement.recover();
}
```

编译器根据事件名对应的原生通道追加尾指令。已有明确的原生终止序列时不重复追加，
因此反编译得到的原始字节可以保持一致。

| 固定事件名 | 触发语义 | 原生槽 | mask | descriptor 字索引 | 自动收尾 |
| --- | --- | --- | --- | --- | --- |
| `dung_reaction` | 肥料玉臭气范围反应 | 0 | 0x40 | 14 | FF F5 |
| `invalid_ground` | 当前地面区域不适用时的处理 | 1 | 0x80 | 13 | FF F6 |
| `player_detected` | 发现玩家／进入警戒 | 2 | 0x20 | 4 | FF FC |
| `awareness` | 感知累积达到阈值、察觉玩家气息 | 3 | 0x10 | 3 | FF FD |
| `rage_entered` | 进入怒态的反应 | 4 | 0x08 | 11 | FF F8 |
| `group_signal` | 接收其他怪物的群体信号 | 5 | 0x04 | 10 | FF F9 |
| `bait_detected` | 发现可响应的肉饵 | 6 | 0x02 | 8 | FF FA |

原生映射适用于 ZZ HD。原生槽仅用于解释二进制映射，不是 DSL 可分配的索引。
事件名表示触发原因，不限定响应动作；触发条件仍有物种差异。
`invalid_ground` 不等于腾空，`group_signal` 不限于同伴受伤，
`bait_detected` 不代表已吃下肉饵。
事件结束不等于对应效果结束，例如怒态可在入口脚本结束后继续持续。

## 6. 原生命令和转义

```text
actions {
    slash = [3:6];
}

fn attack() {
    slash(0);
    action[3:6](0);
    wait(10);
    native(0x92);
}
```

| 写法 | 编码/作用 |
| --- | --- |
| action[g:i](p) | 05 g i p，动作请求 |
| wait(n) | 48 n，原生延迟字段 |
| clear_requests() | 1E |
| nop() | 92 |
| stop() | 68，原生停止并走重启收尾 |
| transition alias | 07 index |
| restart; | 04，重装状态 0 |
| reset; | FF 00，重置主状态及活动事件通道 |
| reset forget_target; | FF F7，清除当前目标槽的追踪数据并重置 |
| native(bytes…) | 原样保留字节，并输出提示 |

`clear_requests()` 清除已接受请求的标志和编号、当前请求优先级、
五类待处理请求标志，以及三类计时请求的已触发标志。请求按优先级处理，
不记录入队顺序或同类请求数量。该指令不修改目标实体、目标坐标或计时值；
计时条件仍满足时，后续更新可以再次产生请求。

actions 别名属于定义它的模块，与函数共用本地名字空间。
事件结束指令由编译器根据具名事件自动补齐。反编译省略匹配的末尾事件结束指令，
条件分支内的提前结束或不匹配的原生结束指令保留为 `native(...)`，以保持字节一致。
区域／路线结束命令（area_end、route_move_end）可显式调用，
一般事件作者不需要手写它们。

自定义函数不接受参数、不返回值；`self` 条件仅限本文列出的形式。
`handler fn` 同样不接受参数，但只能由 `handle` 或处理器尾调用进入。
native 不是绕过安装检查：宽度、原生扫描标记闭合关系和支持的边界均需通过检查。
未闭合条件、执行/跳过宽度存在歧义的 24/62、未知 FF 分派等拒绝安装。

## 7. 原生结构与无损边界

原生 descriptor 的关键关系：

- root[0]：主状态表，07 指令引用。
- root[1]：81 指令引用的脚本表，**不是主状态表**。
- root[15 + group][index]：82 的二级子脚本。
- root[2]：route_ptr_set 使用的表；108604C0 的 descriptor+8 是字节偏移。
- root[6]：地面区域移动脚本。
- root[12]：部分移动数据选择的脚本。
- 七个事件槽按上表读取各自 cell[0]；root[8] 是事件槽，不是 root[2] 的路线表。

索引是一个字节不代表原始表长 256。
绑定层复制 256 项状态和被覆盖子脚本表的寻址窗口以保持原生读取视图，不能将这个窗口当成
反编译的有效状态个数。

反编译采用**部分提取**：状态 0、当前状态、事件入口，以及 `07/81/82/16` 的可追踪引用。
主入口输出为 `fn main()`，其他状态和事件输出匿名入口块，避免生成原生脚本中没有的调用。
状态别名为 `state_<索引>`，子脚本函数名为 `sub_<表索引>_<槽位>`；
实际绑定由 states/events 和 `@slot` 决定。
子脚本使用带 @slot 的普通函数，默认全部输出在同一个 main.mhai。
按表项去重，保留固定层级尾跳转；不依靠相邻指针猜表长。
未确认的条目报告警告并继承；没有发现的表项不能据此判为不可执行。
导出写显式索引、函数定义、必要的 native 指令，并重新编译核对每段字节。
导出范围不保证覆盖完整表边界、移动数据引用图和隐式调用的原始绑定。

## 8. 安装和编辑

自动覆盖由原生初始化 Hook 读取整个工程，验证物种、地图、基座，
编译成功后才生成和发布私有 AI 块。自动 Hook 跳过 species > 0x83 的物种；
调试实例编辑不以该范围或所在区域筛选。

调试编辑器支持：
- 反编译当前实例到一个虚拟 main 文件；
- “加载工程”加载地图专用或默认工程，不立即应用；
- 文件选择器切换主文件与导入模块，各文件保存独立草稿；
- 应用时加载新导入的磁盘模块、保留已编辑文件，统一编译与校验；
- 所有步骤成功后一次发布到所选实例，失败保留原 AI 和草稿；
- 编辑不写回磁盘，复制 DSL 复制当前文件内容。

已发布的内存保留至提供方安全销毁。独立编辑窗口与面板共用草稿。
正在处理命令时禁用目标、文件切换及编辑，防止回复覆盖其他文件。
