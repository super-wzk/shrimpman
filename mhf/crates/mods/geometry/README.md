# Geometry

本领域维护 HD 客户端的几何扩展，没有独立公开服务接口。
`provider` 在 i686 Windows 上启用原生适配和 `GeometryMod::default()`，由
[`mhf-base`](../base/README.md) 始终组合运行，不作为独立 Mod 选择。

detach 移除几何补丁，`prepare_release` 归还额外游戏 DLL 引用；尚未回收的缓冲区由模块持有，
直到宿主完成游戏卸载。默认构建不链接原生实现，`cargo test -p mhf-geometry` 可独立验证
网格转换、三角形拓扑、设备缓存和补丁数据。

武器纹理按实际资源记录所有权与句柄代次，阻止换装清理误释放其他存活武器的贴图，
并回收被相邻纹理槽覆盖的旧句柄；同时覆盖在途创建、场景批量清理和渲染器退出。
拦截异常释放时，控制台会输出
`weapon texture release deferred`，附带玩家槽位、武器/模型 ID 和纹理句柄，最多记录
32 次。`tools/verify_texture_lifecycle.py` 用真实客户端代码复现多贴图武器的槽位重叠，
`tools/verify_renderer.py` 对比原生和扩展后的绘制路径；这些模拟不能代替多人游戏复测。

装备和地图统一使用 `cache::Buffer` 处理容量校验、扩容、复用与旧分配保留；各加载入口
只计算所需字节数，并按各自的原生时序更新指针。
地图 PAC 在读入前按文件、文件名和活动贴图的总大小扩容；FMOD、FSKL 在解包前按
实际输出长度分别分配，容量不足时按 2 的幂增长并复用，取消固定的 64/32/4 MiB 上限。
装备在整批构造完成后、地图 FMOD/FSKL 在对应构造器返回后，由 RAII 守卫的 `Drop`
统一结束本次使用并触发回收。同步调用正常返回时自动执行；异步队列须先确认工作线程
和完成回调结束，等待或 Rust unwind 不算完成。实际内存释放由 `Vec` 的 `Drop` 负责。
新地址发布成功时回收已确认结束的旧分配，当前分配继续复用；取消、失败或未经确认就
再次使用的分配保留到 DLL 卸载，迟到的完成回调不能确认新一轮使用。共享 PAC 工作区
仍保留旧分配至卸载。模型分配或头部校验失败时跳过解包，发布有效的空模型。

动态 PAC 读取覆盖 `stage-hd\st*.pac` 与 `stage\st*.pac`；解包覆盖地图和两个共用
地图解包工作区的场景效果入口。原始 PAC 工作区仍保留原生 14 MiB 的兼容下限，其余
使用同一工作区的 NPC、动作等加载路径没有改为动态扩容。装备、怪物的其他解包
工作区别名保持原有布局；地图对象、材质数量、32 位进程地址空间和 D3D9 设备限制仍然存在。
`tools/verify_stage_cache.py` 验证真实客户端的读取、解包与指针切换；不代替游戏内地图复测。
